## 7. Implementation notes & gotchas

- **Server-3D vs client-2D policy:** server-created 3D sounds bypass the client SFX setting — reserve for *social* moments (steal alarm, lever, door zap, collect ka-ching, construction rumble); always set `RollOffMaxDistance`. Personal feedback goes through the gated client path.
- **Bank rebuilds destroy everything:** `BankBuilder.Build` wipes `workspace.CucumberBank` on every relayout — any loop sound/beacon on bank geometry dies. Lazy re-creation inside `SetLasers`/`RefreshSecurityUI` self-heals (Relayout already calls them per stall). Sounds on stored cucumber *models* survive (models are detached, not destroyed), but add any new attachment names to `StripPodiumAttachments` so they don't ride along on a thief's arm.
- **Server `ParticleEmitter:Emit()` doesn't render for clients** — burst visuals must be client-side (net event) like the vendor's existing burst.
- **Spam register:** pet hits (0.6s tick), Indicate popups, smash score blips, auto-hatch reveals, global click sound, new hover ticks — every one needs its throttle designed in from the start (§2.1's throttle keys).
- **BreakablesClient's pooled playSound caps at 3s** — long tails (fanfares, alarms) need the clone→Ended→Destroy pattern instead.
- Steal hold-progress feedback can only be thief-side client (`PromptButtonHoldBegan` filtered to `StealPrompt`) — the server never sees holds; victim-side hold warning would need new remotes (skip).
